# 페이지 우선 시나리오 사용자 흐름

작성일: 2026-09-14

## 목적

QA 사용자가 자연어 TC의 완전한 구조화에 먼저 의존하지 않고, 실제 페이지에서 확인된 요소로 기본 자동화 시나리오를 만든 뒤 자연어 TC로 누락 요구사항을 보강한다.

핵심 흐름은 다음과 같다.

`페이지 분석 → 기본 시나리오 생성 → TC 비교·보강 → 사용자 검토 → 승인 → 실행 설정 → 실행 계획 확인 → Worker 실행 → 증적 확인`

## 사전 조건

- 승인된 사용자가 로그인할 수 있어야 한다.
- 실행 환경과 navigation/resource 허용 도메인이 등록돼 있어야 한다.
- 분석 URL은 HTTP(S)이며 인증정보, query, fragment를 포함하지 않아야 한다.
- 현재 페이지 우선 기능은 한 페이지, 읽기 전용, AI 호출 0회 범위다.

## 정상 사용자 시나리오

### 1. AI 시나리오 진입

1. 사용자는 로그인 후 왼쪽 메뉴에서 `AI 시나리오`를 선택한다.
2. 프론트는 `AI 시나리오 초안` 화면과 현재 범위 `PHASE 2 · AI 0회`를 표시한다.
3. 사용자는 페이지에서 검증된 요소가 기본 시나리오의 근거이고 자연어 TC는 선택적 보강 자료라는 설명을 확인한다.

### 2. 분석 대상 입력

1. 사용자는 실행 환경을 선택한다.
2. 프론트는 환경 이름, 기준 URL 및 허용 범위를 표시한다.
3. 사용자는 분석할 시작 URL을 직접 입력한다. 환경 기본 URL을 자동으로 실행 대상으로 채우지 않는다.
4. 필요하면 선택한 단일 자연어 TC의 대상, 행동, 기대 결과를 입력한다.
5. 환경, URL 또는 TC가 변경되면 이전 discovery, 시나리오, 검토 revision 및 승인 버전을 화면 상태에서 폐기한다.

현재 `AI 시나리오` 화면에는 파일 업로드가 없다. XLSX/CSV/DOCX/TXT 가져오기는 별도 `테스트 케이스` 화면에서 수행하며, 가져온 단일 TC를 페이지 우선 화면으로 직접 넘기는 연결은 후속 범위다.

### 3. 페이지 분석

1. 사용자가 `페이지 분석 시작`을 누른다.
2. 중복 클릭과 환경·URL·TC 변경을 요청 완료 전까지 막는다.
3. 프론트는 `페이지 접속 → 요소 수집 → 후보 검증 → 시나리오 초안` 진행 상태를 표시한다.
4. 완료 시 페이지 제목, 최종 URL, fingerprint, 검증 요소 수를 표시한다.
5. 검증 요소가 0개이면 완료로만 표시하지 않고 자동 시나리오를 만들 수 없다는 차단 상태와 재분석 안내를 보여야 한다.

### 4. 기본 시나리오 생성

1. 유효한 요소가 한 개 이상이면 사용자가 `기본 시나리오 생성`을 누른다.
2. 서버는 실제 페이지에서 유일성과 표시 상태가 확인된 `data-testid` 또는 role+accessible name 요소를 visible assertion 후보로 생성한다.
3. 프론트는 왼쪽에 페이지 근거 단계, 오른쪽에 TC 비교 항목을 표시한다.
4. 현재 자동 범위는 표시 assertion이다. 클릭, 입력, 로그인, 다중 페이지 탐색, iframe 내부 행동 및 업무 의미 추론은 자동 생성하지 않는다.

### 5. TC 비교·보강

1. TC를 입력했다면 각 요구사항을 `MATCHED`, `PAGE_ONLY`, `TC_ONLY`, `CONFLICT`, `NOT_AUTOMATABLE`로 표시한다.
2. 사용자는 각 행에서 `시나리오에 추가`, `수동 검증`, `문구 수정`, `제외` 중 하나를 선택한다.
3. `ADD`는 검증된 `MATCHED/PAGE_ONLY` 근거가 있는 항목에만 허용한다.
4. `MANUAL/EXCLUDE` 항목은 자동 실행과 PASS 범위에 포함하지 않는다.
5. 각 선택은 서버 revision에 저장하며, 늦은 응답이나 다른 TC의 응답이 현재 화면을 덮어쓰지 않아야 한다.
6. 409 revision 충돌 시 자동 재시도하지 않고 최신 상태를 가져와 사용자가 다시 검토하도록 안내한다.

### 6. 승인

1. 모든 비교 행을 결정하고 자동 실행 가능한 단계가 한 개 이상일 때만 `승인 후 실행 설정`을 활성화한다.
2. 승인 시 최근 discovery, fingerprint, 환경 및 revision을 다시 검증한다.
3. 성공 응답의 새 `versionId`만 실행 설정과 Worker 실행에 사용한다.
4. 승인된 버전은 변경하지 않으며 재분석·재구조화 시 새 검토 버전을 생성한다.

### 7. 실행 설정과 계획 확인

1. 사용자는 환경, 브라우저, viewport, locale, 계정, 제한 시간, AI 호출 한도, 재시도 및 위험 행동 승인을 확인한다.
2. 페이지 분석에 사용한 환경은 잠그고 허용 도메인을 표시한다.
3. `실행 예정 시나리오 확인`을 누르면 서버의 plan revision, plan hash, URL, selector, assertion 및 전체 단계가 표시된다.
4. 계획이 `EXECUTABLE`일 때만 `이 시나리오로 실행`을 허용한다.

### 8. 실행과 결과 확인

1. Worker 실행 중 프론트는 실제 상태, 단계별 action, URL/selector, PASS/FAIL, 오류 코드와 증적 수를 표시한다.
2. 화면 영역에는 라이브 영상이 아니라 Worker가 저장한 최신 실제 viewport PNG를 표시한다.
3. 완료 후 사용자는 결과 상세에서 전체 결과, 단계별 상태, 오류 코드, 증적 및 선택 단계의 스크린샷을 확인한다.
4. 증적이 없는 과거 실행은 그 사실과 새 버전 재실행 안내를 표시한다.

## 오류와 복구

- 접속·시간 초과·브라우저·내부 오류는 입력을 보존한 지속 오류 카드로 표시하고 사용자가 직접 재시도한다.
- 허용되지 않은 URL은 분석 전에 차단한다.
- 요소 0개 또는 실행 선택 0개는 승인 전에 차단한다.
- 페이지 fingerprint가 변경되면 `DISCOVERY_STALE`로 실행을 막고 새 분석을 요구한다.
- 승인·실행 버튼은 요청 중 비활성화하고 중복 요청을 만들지 않는다.

## 현재 구현 해석

현재 화면 구조는 `페이지 분석으로 기본 시나리오를 만들고 TC로 빠진 요구사항을 보강한다`는 제품 방향과 일치한다. 다만 구현 능력은 규칙 기반 표시 검증까지이며, AI가 페이지를 탐색해 클릭·입력·이동을 조합한 업무 시나리오를 제안하는 기능은 아직 포함하지 않는다.
